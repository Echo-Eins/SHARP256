# Носители: журналы лаборатории

Что сделано и почему — PROTOCOL.md, раздел «Carriers other than UDP», и
THREAT_MODEL.md (Н7, Г37–Г39).

`scripts/carrierlab/carrierlab.py matrix` — каждая клетка: настоящие
`sharp-relay`, `sharp-receiver` и `sharp-sender` в своих сетевых
пространствах имён, между ними маршрутизатор C, который делает с трафиком
одной стороны (отправителя или получателя) то, что делают такие сети. Всё,
что «мешает», — ядро и чужой код: правила nftables (сброс, `limit rate
over`, перенаправление на прокси), задержка tc netem (10 мс на каждом выходе
C, круг 20 мс), TLS-инспектирующий прокси на модуле `ssl` Python
(`scripts/carrierlab/mitm.py`, OpenSSL с обеих сторон, кода SHARP-256 в нём
нет). У хостов клетки адреса одного семейства.

* `matrix.md` — итог: чем кончилась каждая клетка на IPv4 и на IPv6.
* `<сторона>-<блокировка>-ipv<семейство>.log` — строки журналов клетки,
  которые говорят, каким путём шла передача: отправителя, получателя,
  ретранслятора и прокси.

Что значат клетки:

| Блокировка | Что делает C |
|---|---|
| `open` | ничего — контроль |
| `udp_blocked` | сбрасывает весь UDP стороны |
| `udp_cut` | то же через 1,5 с после начала передачи |
| `udp_policed` | пропускает UDP к получателю не быстрее 250 кБ/с (корзина 64 КиБ), TCP не трогает |
| `tcp443_only` | выпускает только TCP на порт 443, впускает только ответы |
| `tls_inspected` | то же, и TLS на 443 перенаправлен на прокси, который завершает его своим сертификатом и открывает свой к ретранслятору |

Итоги: `UDP` — прямо по UDP; `TCP` — по потоку прямо к получателю;
`relay/UDP`, `relay/TCP`, `relay/TLS` — через ретранслятор по этой несущей;
«then» — переход посреди передачи; «held back» — UDP опознан задушенным, и
проба оставила сессию на TCP; «receiver over TLS» — получатель достучался до
ретранслятора только по TLS; «refused» — перехваченная сессия TLS опознана
и не использована, о чём сказано в журнале. Что ожидалось для каждой
клетки — `EXPECTED` в `carrierlab.py`; файл должен прийти целым везде, где
передача не отвергнута.

Где двух исходов допустимо оба (получатель за сетью без UDP, IPv4 против
IPv6 в `matrix.md`): ретранслятор по UDP ответил раньше, чем отправитель
набрал TCP, — тогда сессия сперва идёт через него и через несколько секунд
переходит на прямой поток; не ответил — сразу прямой поток.

Окружение прогона: 2026-10-01, Linux 6.19.2 (Gentoo), nftables 1.1.6,
iproute2 6.18.0, OpenSSL 3.5.5, Python 3.13.11; отладочные сборки
бинарников (`target/debug`, `--all-features`).

```
cargo build --all-features --bins
python3 scripts/carrierlab/carrierlab.py matrix --markdown docs/evidence/carriers/matrix.md --logs docs/evidence/carriers
python3 scripts/carrierlab/carrierlab.py one udp_policed --side receiver --family 6 -v   # одна клетка, подробно
```
