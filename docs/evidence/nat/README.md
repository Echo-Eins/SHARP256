# Журналы лаборатории NAT

Сырые журналы, из которых составлен раздел 4 [docs/NAT.md](../../NAT.md).
Каждый файл — вывод одного сценария `scripts/natlab/natlab.py`, как он
был напечатан, с шапкой: коммит кода, хэши `sharp-sender` и
`sharp-receiver`, дата, ядро, версии nftables, miniupnpd, coturn и Python,
переменные окружения сценария и сама команда. В конце — код завершения
сценария: ноль, только если каждая пара повела себя так, как говорит
теория (раздел 2 NAT.md).

Все журналы, кроме четырёх «до исправления» (см. ниже), сняты на коде
коммита `47364fb2f362bc8bb234ce996c110b8ea20e1ed9`, одними и теми же
бинарниками (`cargo build --release --no-default-features --features
nat-traversal --bins`; хэши — в шапке каждого). Журналы, начатые после того,
как посреди прогона был сделан коммит
`8e1fc0c875f106844679c468fd746ef9ba44c146`, называют в шапке его: он меняет
только документацию (`git diff 47364fb 8e1fc0c -- src scripts tests
Cargo.toml Cargo.lock` пуст), и бинарники в их шапках те же.

* **IPv4** — ядро Linux 6.18.44 (контейнер, IPv6 в ядре выключен);
* **IPv6** (`ipv6-*`, `portmap6`, `lan-v6`, `probe-v6*`) — ядро Ubuntu
  7.0.0-34-generic в виртуальной машине QEMU с эмуляцией процессора (TCG),
  собранной по [scripts/natlab/vm/README.md](../../../scripts/natlab/vm/README.md).

| Файл | Что проверяет |
|---|---|
| `oracle.log` | виды NAT сами по себе: независимый от протокола скрипт измеряет отображение и фильтрацию каждого |
| `matrix-relay-carries.log` | 36 пар видов NAT, знакомит и при необходимости несёт `sharp-relay` (1 МБ) |
| `matrix-relay-carries-long.log` | то же, передача 30 МБ на 20 Мбит/с: успевает ли сессия уйти с ретранслятора |
| `matrix-relay-introduces.log` | ретранслятор только знакомит, нести не может |
| `matrix-cards.log` | без сервера: две контактные карточки, переданные «вручную» |
| `matrix-addresses.log` | без сервера и карточек: адреса `IP:PORT`, «прочитанные с экрана» |
| `matrix-dht.log` | без сервера: встреча через Mainline DHT (узел `dht_node.py`) |
| `matrix-turn-long.log` | карточки и TURN-сервер coturn, 30 МБ |
| `matrix-isolated-relay.log`, `matrix-isolated-turn.log` | сети не достают друг друга вовсе: всё несёт сервер |
| `portmap.log` | PCP, NAT-PMP, UPnP-IGD против miniupnpd; каждая строка приводит слова демона о запросе, сделавшем проброс (для NAT-PMP PCP на роутере отрезан), и правило, которое он поставил в nftables роутера |
| `portmap-taken.log` | то же, когда порт 5555 уже проброшен другому: какой порт выбрал роутер (PCP, NAT-PMP, UPnP `AddAnyPortMapping` у IGDv2, свои порты наугад у IGDv1) и что получатель опубликовал именно его |
| `portmap-anycast.log` | PCP провайдера: роутер ничего не транслирует, NAT и сервер PCP — у провайдера, который слушает только адрес anycast `192.0.0.9` (RFC 7723) |
| `cgn.log` | провайдерский NAT перед домашним роутером — два NAT подряд, с любой стороны |
| `lan.log`, `lan-v6.log` | mDNS: объявлен и спрошен, объявлен и не спрошен, спрошен и не объявлен |
| `samenat.log` | двое за одним NAT: локальный адрес, ретранслятор, и NAT с петлёй (hairpinning), где они встречаются по внешним адресам; что получатель измерил о петле |
| `timeout.log` | NAT, забывающий отображение за 8 с: получатель остаётся достижимым |
| `early.log` | отправитель спрашивает ретранслятор раньше, чем получатель там зарегистрировался |
| `fallback.log` | прямой путь перерезан посреди передачи: сессия возвращается на сервер |
| `probe-all.log`, `probe-all-addresses.log` | `sharp-probe` для каждой пары: предсказывает ли он то, что делает передача (по карточкам и по адресам), и верно ли каждый хост назвал свою сеть — внешний адрес, отображение, фильтрацию, нумерацию портов, петлю |
| `mutation.log` | ловит ли лаборатория пропажу метода: пары, которым нужно предсказание портов или «дни рождения», на бинарниках коммита и на сборках того же коммита, где метод выключен одной правкой (правки — в шапке) |
| `ipv6-*.log` | межсетевые экраны IPv6 (RFC 6092) и обе семьи сразу: те же способы встречи |
| `portmap6.log` | пинхолы IPv6: PCP, PCP по адресу anycast `2001:1::1`, UPnP IGD2 `AddPinhole` (PCP отрезан), и контроль без демона |
| `probe-v6.log`, `probe-v6-addresses.log` | `sharp-probe` по IPv6, и верно ли каждый хост назвал свой экран |

Четыре журнала сняты **до** исправлений или добавлений и оставлены, чтобы
было видно, что сценарий ловит то, ради чего написан (шапка каждого говорит,
на каких бинарниках):

| Файл | Что было не так |
|---|---|
| `fallback-before-fix.log` | сессия, встретившаяся «днём рождения» на отдельном сокете, не возвращается на ретранслятор, когда прямой путь умирает: передача не доходит за 150 с |
| `portmap-anycast-before-fix.log` | PCP провайдера до того, как PCP стали спрашивать по адресу anycast: в той же топологии получатель не получает проброса ни в одной из 12 строк (бинарники `1b4f84a`, сценарий — как в коммите `90f4775`) |
| `ipv6-turn-long-before-fix.log` | сессия качается между прямым путём и TURN и в 10 ячейках из 18 кончается на TURN при открытом в обе стороны прямом пути (коммит `068fe71`, до правила `DIRECT_GRACE`) |
| `probe-all-before-fix.log` | разведка до того, как фильтрацию стали мерить на отдельном отображении: хост за `restricted` называет свой NAT «пускающим всех», верны 60 отчётов из 72 (бинарники `0af7882`, сценарий — тот же, что у остальных журналов) |

Воспроизвести: раздел 7 NAT.md. Ячейки таблиц раздела 4 прочитаны из этих
файлов по правилам `scripts/natlab/grid.py`, который печатает таблицу
любого одного журнала.
