# Журналы замеров постоянства времени

Вывод `scripts/dudect.sh` — замеров в духе dudect (Reparaz, Balasch,
Verbauwhede, DATE 2017), описанных в `src/crypto/dudect.rs`: операция
выполняется на входах двух классов вперемешку, и t-критерий Уэлча
отвечает, различаются ли распределения времени. |t| > 4,5 — различаются
(порог статьи). Шапка каждого журнала называет коммит, компилятор,
процессор, ядро и ядро процессора, к которому привязан замер.

* `dudect.log` — код коммита `8a76c1b`, без изменений. Ни одна проверка
  секретов не различает классы (|t| ≤ 2,5); контроль — сравнение,
  останавливающееся на первом различии, — различает (|t| около 1100), то
  есть метод утечку такого рода видит. Строки «reported only» — не
  проверки: валидность MAC не секрет (что будет дальше, её и так
  показывает), а `from_str_radix` приведён для сравнения с кодом без
  ветвлений.
* `dudect-before-fix.log` — тот же код с одной правкой, приведённой в
  шапке: эпоха в `DirectionKeys::open` сравнивается ветвлениями, как до
  исправления. Поддельный пакет с заголовком «сохранённой» эпохи
  отвергается быстрее, чем со случайным: |t| 8,7. Тест на этом месте
  падает, и пакеты ChaCha20 уже не замеряются.

Замер говорит о том, что различия не нашлось на этой машине, этим
компилятором и за столько-то прогонов; это свидетельство, а не
доказательство, и на другом процессоре его надо повторить:

```
scripts/dudect.sh [ядро процессора]
```
