# Небезопасный код

Весь `unsafe` в крейте — это вызовы в систему, которых нет в стандартной
библиотеке и в `socket2`, и чтение того, что система вернула. Своих
структур данных на сырых указателях, `unsafe impl`, `transmute` нет.

## Правила (их проверяет компилятор)

* `unsafe_code = "deny"` на весь крейт (`Cargo.toml`, `[lints]`).
  Разрешение `#[allow(unsafe_code)]` стоит только на функциях и модулях
  из таблицы ниже, у каждого в комментарии названы вызовы. Новый `unsafe`
  без явного разрешения не соберётся.
* У каждого блока свой комментарий `// SAFETY:`, почему он корректен
  (`clippy::undocumented_unsafe_blocks`).
* Одна небезопасная операция на блок
  (`clippy::multiple_unsafe_ops_per_block`), так что обоснование говорит
  об одной вещи.
* В `unsafe fn` каждая операция тоже в своём блоке
  (`unsafe_op_in_unsafe_fn`); контракт вызывающего описан в `# Safety`.

Clippy с `-D warnings` в CI проверяет Linux, Windows, macOS и FreeBSD.
Итого 52 блока в программе и 14 в тестах, на всех платформах вместе.

## Где

| Место | Вызовы | Платформы | Почему не безопасной обёрткой |
|---|---|---|---|
| `address/dns.rs`: `getaddrinfo`, `addresses_in` | `getaddrinfo`, `gai_strerror`, `freeaddrinfo`; чтение списка `addrinfo` | Unix, Windows | Нужен запрос по одному семейству (Happy Eyeballs, RFC 8305). `ToSocketAddrs` спрашивает оба сразу и ждёт медленный ответ |
| `address/dns.rs`: `winsock_ready`, `interface_index` | `WSAStartup`, `if_nametoindex` | Unix, Windows | В std нет |
| `crypto/secret.rs`: `mod os` | `sysconf`, `mlock`, `munlock`, `madvise`; `GetSystemInfo`, `VirtualLock`, `VirtualUnlock`, размеры рабочего множества | Unix, Windows | В std нет |
| `crypto/keystore.rs`: `mod dpapi` | `CryptProtectData`, `CryptUnprotectData`, `LocalFree` | Windows | В std нет |
| `file/mod.rs`: `available_space` | `statvfs`, `GetDiskFreeSpaceExW` | Unix, Windows | В std нет |
| `file/mod.rs`: `system_rename_no_replace` | `renameat2` (системный вызов), `renamex_np`, `MoveFileExW` | Linux, macOS, Windows | Переименование без замены: в std его нет |
| `nat/birthday.rs`: `descriptor_limit` | `getrlimit` | Unix | В std нет |
| `transport/socket.rs`: `set_int_option`, `v6_only`, `set_dont_fragment`, `disable_udp_connreset` | `setsockopt`, `getsockopt`, `WSAIoctl` | Unix, Windows | В `socket2` нет `SO_RCVBUFFORCE`, `IP_MTU_DISCOVER`, `IPV6_DONTFRAG`, `SIO_UDP_CONNRESET`. Его `only_v6` на Windows читает ответ в неинициализированные четыре байта и проверяет, что их пришло четыре, только в отладочной сборке; здесь ответ ложится в обнулённые, сколько бы из них система ни заполнила |
| `tests/e2e.rs`: `mod netns` (только тесты) | `ioctl` интерфейсов | Linux | Тест сам поднимает интерфейс в своём сетевом пространстве имён |

## Что нашла ревизия (исправлено)

* **DPAPI, пустой ответ.** Результат `CryptUnprotectData` брался как
  срез по его указателю и длине. Пустой ответ с нулевым указателем давал
  срез из нулевого указателя — неопределённое поведение при любой длине.
  Вызвать это можно файлом идентичности, запечатанным под той же учётной
  записью Windows. Теперь пустое — это пустое. Тест
  `an_empty_blob_is_nothing`: старый код Miri останавливает
  («encountered a null reference»), новый проходит.
* **Список `getaddrinfo`, выравнивание.** Адрес `sockaddr_in` или
  `sockaddr_in6` брался по ссылке, а ссылка требует выравнивания на 4.
  Поле `ai_addr` — `*mut sockaddr` с выравниванием 2, большего никто не
  обещает. Системные реализации на деле выравнивают, но это допущение, а
  не гарантия. Теперь адрес копируется `read_unaligned`, а обход списка
  вынесен в `addresses_in`, который проверяется на списке, собранном в
  тесте, с адресами по невыровненным местам
  (`addresses_are_read_from_the_list_wherever_they_lie`). Прежнее чтение
  по ссылке тест ловит дважды: отладочная сборка падает («misaligned
  pointer dereference»), Miri останавливает («unaligned reference»).
* **`renameat2` через `syscall`.** Аргументы уходили как `int`, а
  `syscall(2)` берёт их как `long`. Работало только потому, что ядро само
  обрезает их до `int`. Теперь передаются как `long`.
* **Тест `netns`.** Имя интерфейса длиннее `ifr_name` обрезалось бы без
  завершающего нуля; теперь такое имя — ошибка теста.
* Там, где один комментарий `SAFETY` покрывал несколько операций или его
  не было (`statvfs`, `QuadPart`, `GetSystemInfo`, рабочее множество
  Windows), у каждой операции теперь своё обоснование. Два почти
  одинаковых `setsockopt` на Unix сведены в одну обёртку.

## Miri

Miri исполняет Rust и находит неопределённое поведение, но вызовов в
систему, кроме немногих, которые он эмулирует, не исполняет. Поэтому
большая часть блоков выше ему недоступна. `scripts/miri.sh` (CI, задача
«Miri») гоняет то, что доступно:

* обход списка `getaddrinfo` — на списке из теста;
* `Locked` и `SecretKey` (`crypto::secret`). Вызовы закрепления памяти
  под Miri не делаются: `cfg(miri)` оставляет ключи как на системе без
  закрепления, а остальное проверяется;
* пустой ответ DPAPI — код для Windows, который Miri исполняет и на Linux
  (`--target x86_64-pc-windows-gnu`).

Выравнивание проверяется символически (`-Zmiri-symbolic-alignment-check`):
по тому, что обещает выделение памяти, а не по адресу, который ему
случайно достался. Первый вариант теста клал адреса на буфер + 1, и без
флага Miri прежнее чтение по ссылке пропустил: буфер лёг на нечётный
адрес, и адрес внутри вышел выровненным. Теперь тест кладёт адреса на
один байт после кратного четырём, и старое чтение ловится и без флага; с
ним — при любом размещении.

Под Miri прогнаны и модули без вызовов в систему: `protocol` (18 тестов,
около 9 минут) — неопределённого поведения нет ни в них, ни в
зависимостях на этом пути. `crypto::transport` за восемь минут не
закончился. В CI такие прогоны не входят: слишком долго для каждого
изменения.

Журналы — `docs/evidence/unsafe/`: `before-fix.log` (каждое исправление
по очереди откачено: отладочная сборка и Miri останавливают старый код,
закоммиченный проходит), `miri.log` (`scripts/miri.sh`),
`miri-modules.log`.

## Что остаётся

Вызовы в систему проверяются чтением документации и тестами, которые их
выполняют: разрешение имён, закрепление памяти (`keys_are_locked_here`
смотрит `VmLck` ядра), запечатывание DPAPI (`windows_seals_and_opens_it`
в CI на Windows), переименование без замены, опции сокетов. Динамические
проверки памяти во время работы (ASan, TSan) — следующий пункт плана, B2.
