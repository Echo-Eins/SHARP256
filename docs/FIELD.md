# Полевые испытания

Лаборатории (`scripts/natlab`, `scripts/carrierlab`) доказывают то, что
можно построить из ядра Linux. Настоящие роутеры, операторские NAT, мобильные
сети, корпоративные межсетевые экраны и сети с DPI ведут себя по-своему, и
проверить это можно только так: двое людей в разных сетях передают друг
другу файлы и присылают журналы. Этот документ — для них.

Ничего, кроме двух компьютеров и способа переслать друг другу строку текста
(мессенджер, почта), не нужно. Ретранслятор помогает там, где прямой путь
невозможен; если он есть — его адрес и ID дал тот, кто его поднял
([RELAY.md](RELAY.md)).

## Что нужно

* `sharp-probe`, `sharp-receiver`, `sharp-sender` — из выпуска или собранные
  (`cargo build --release --bins`, README «Сборка»), одной версии у обоих.
* Linux или macOS: `scripts/field/field.sh` из репозитория (рядом с
  бинарниками или с `SHARP_BIN=<каталог бинарников>`). Windows — команды
  ниже, без скрипта.
* Тестовый файл из случайных данных, **не личный**:
  `head -c 200M /dev/urandom > test.bin`; в PowerShell —
  `$b = [byte[]]::new(200MB); [Random]::new().NextBytes($b); [IO.File]::WriteAllBytes("$PWD\test.bin", $b)`.

## Как прогнать один сценарий

Оба — в каталоге, где будут лежать журналы (`./sharp-field`).

1. **Оба:** `field.sh probe`. Через несколько секунд программа скажет, как
   вашу сеть видно снаружи, и напечатает карточку `shc1-…`. Если есть
   ретранслятор — `field.sh probe --stun <адрес ретранслятора>:3478`: он
   измеряет больше, чем публичные серверы. Строки `Network:`/`IPv4:` и
   карточку пришлите друг другу: `sharp-probe` второго вставит её и скажет,
   доходят ли пакеты (обоим нужно вставить чужую карточку в течение двух
   минут). Это проверка без файла.
2. **Получатель:** `field.sh receive` (с ретранслятором — `field.sh receive
   --relay <ID ретранслятора>@<адрес>:5560`). Он печатает `Your card:` и
   `Senders use: sh4-…@…`; одну из строк — отправителю.
3. **Отправитель:** `field.sh send test.bin <карточка или строка Senders
   use>` (с ретранслятором добавить `--relay <ID>@<адрес>:5560`). Он
   печатает `Your card:`/`Addresses:` — это обратно получателю, который
   вставляет строку в своё окно и нажимает Enter (шаг не нужен, если
   `Network:` получателя говорит `reachable from outside`).
4. Ждите `Done:` у отправителя и `Received` у получателя (или ошибку;
   отправитель ждёт до пяти минут). Получатель — Ctrl-C.
5. **Оба:** `field.sh pack` — архив отчётов; пришлите его тому, кто собирает
   результаты, вместе с заполненной строкой таблицы (ниже).

Повторные прогоны — те же команды: ключи сохраняются в `sharp-field/keys`,
и ID получателя от прогона к прогону тот же.

### Windows

В PowerShell, в каталоге с бинарниками:

```
$env:NO_COLOR = 1; mkdir -Force sharp-field\keys, sharp-field\reports, sharp-field\received | Out-Null
.\sharp-probe.exe --identity sharp-field\keys\probe.key --log-level debug 2>&1 | Tee-Object sharp-field\reports\probe.txt
.\sharp-receiver.exe --headless --identity sharp-field\keys\receiver.key --state-dir sharp-field\state --output sharp-field\received --log-level debug 2>&1 | Tee-Object sharp-field\reports\receiver.txt
.\sharp-sender.exe test.bin <карточка> --headless --identity sharp-field\keys\sender.key --state-dir sharp-field\state --log-level debug 2>&1 | Tee-Object sharp-field\reports\sender.txt
Compress-Archive sharp-field\reports sharp-field-report.zip
```

(Эти команды не проверялись на Windows: у автора её нет. Скрипт для
Linux и macOS проверен.)

## Сценарии

По возможности — по порядку: каждый следующий сложнее.

| № | Сеть отправителя | Сеть получателя | Как встречаются | Что проверяем |
|---|---|---|---|---|
| 1 | домашний роутер | домашний роутер (другой город или провайдер) | карточки | прямой путь через два NAT |
| 2 | то же | то же | ретранслятор (`--relay`) | путь через ретранслятор и уход с него на прямой |
| 3 | мобильный интернет (раздача с телефона) | домашний роутер | карточки, затем ретранслятор | операторский NAT (CGN) |
| 4 | мобильный | мобильный (другой оператор) | ретранслятор | два CGN |
| 5 | корпоративная, гостевая или публичная Wi-Fi | домашний | ретранслятор с TLS | закрытый UDP, только 443 |
| 6 | любая из уже прошедших | любая | `--dht` у обоих, отправителю — только ID получателя | встреча через настоящую DHT |
| 7 | любая из прошедших | любая | как в ней | файл 2–5 ГБ; посреди передачи на 30 с отключить сеть у одной стороны, затем — смена сети (Wi-Fi → мобильный) |

Сеть с DPI или с ограничениями (школа, корпоративный прокси, оператор с
белыми списками) — отдельный ценный сценарий: опишите, что известно о её
ограничениях, и что увидела программа.

## Что прислать

Архив `field.sh pack` от **обоих** и строку таблицы:

| Поле | Пример |
|---|---|
| сценарий | 3 |
| сеть отправителя | мобильный интернет, оператор X, раздача с телефона |
| сеть получателя | домашний роутер TP-Link Archer C6, провайдер Y |
| что сказал `sharp-probe` у каждого | строки `Network:`/`IPv4:`/`IPv6:` |
| дошли ли пакеты в проверке карточками | да/нет, откуда |
| передача | удалась / нет, сообщение об ошибке |
| путь | из журнала отправителя: `Connected to …`, `the session runs over TCP now`, `relay … will carry …`, `receiver address … proven` |
| время до начала и скорость | из строки `Done:` |
| что ещё заметили | |

Модель роутера и провайдера — по желанию, но именно это делает результат
полезным для других.

## Приватность

В журналах — IP-адреса обеих сторон (внешние и домашние), ID, имена и
размеры файлов, время. **Ключей и содержимого файлов в них нет** (это
проверяет тест, THREAT_MODEL.md Г31), и `pack` не берёт каталоги `keys`,
`state` и `received`. Пересылайте архив тем способом, которому доверяете;
в репозиторий попадает только обезличенная сводка
([evidence/field/](evidence/field/)), без адресов.

Режим `--dht` публикует адрес получателя в открытой DHT, а отправитель
спрашивает о нём её узлы: они узнают ваши адреса (как и любые узлы
BitTorrent).
