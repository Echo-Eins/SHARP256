# Цепочка поставок

Всё, что входит в программу и в её выпуски помимо своего кода: чужие
крейты, инструменты сборки, действия CI. Здесь написано, как это
проверяется и что ещё не проверено.

## Что тянет сборка

| Сборка | Крейтов (Linux) | На всех целях |
|---|---|---|
| без GUI (`--no-default-features --features nat-traversal`) | 109 (было 132) | 152 (было 179) |
| без GUI, с TLS к relay (`--features nat-traversal,tls`; так собираются выпуски) | 115 | 158 |
| полная, с GUI | 311 (было 316) | 449 (было 456) |

Считаются обычные зависимости и зависимости сборки, без зависимостей
тестов и без самого `sharp256` (`docs/evidence/supply-chain/deps.log`).

Из сборки без GUI убраны 23 крейта; что при этом потеряно, сказано у
каждого пункта:

* `tracing-subscriber` без `env-filter` и `tracing-log`: восемь крейтов —
  `regex`, `regex-automata` и `regex-syntax` в двух версиях, `matchers`,
  `log`, `tracing-log` (и `overload`, ушедший с обновлением
  `nu-ansi-term`). `--log-level` и
  `RUST_LOG` по-прежнему принимают уровень (`debug`) и список
  `цель=уровень` (`sharp256::nat=trace,info`). Фильтров по спанам и полям
  (`[span{поле=x}]`) больше нет. Библиотеки GUI пишут журнал через `log`,
  поэтому фича `gui` возвращает `tracing-log`.
* `tokio-util` без `rt`: пять крейтов — `futures-util` с `futures-macro`,
  `futures-task`, `pin-utils`, `slab`. Из него нужен только
  `CancellationToken`.
* `clap` без цвета: шесть крейтов; справка и ошибки теперь без
  раскраски.
* `rand` только с системным источником (`OsRng`): три крейта генератора
  ChaCha для `thread_rng` — `rand_chacha`, `ppv-lite86`, `zerocopy`. Случайность,
  не нужная криптографии (дрожание интервала, перемешивание портов),
  тоже берётся у системы: вызовов немного, а источник один.

TLS к relay (фича `tls`, по умолчанию включена) добавляет шесть крейтов:
`rustls` 0.23 (только TLS 1.3, провайдер `ring`), `tokio-rustls`,
`rustls-pki-types`, `rustls-webpki`, `ring` и `untrusted`. Выбран `ring`, а
не `aws-lc-rs`: тому для сборки нужны CMake и намного больше кода на C.
`ring` всё равно компилирует C и ассемблер для целевой платформы, отсюда
три следствия:

* фича отделена от `nat-traversal`, и санитайзеры, loom и Miri собирают
  без неё: в чужой C-код они не заглядывают, а MemorySanitizer принял бы
  его записи за неинициализированную память;
* clippy для Windows и macOS в CI идёт без `tls`: на Linux нет
  C-компилятора под эти цели. Тесты на самих Windows и macOS собирают
  TLS как обычно;
* воспроизводимая сборка без GUI теперь компилирует C-код `ring` gcc из
  образа. Совпадение байтов при этом ещё не проверялось (см. «Что
  осталось»).

Обновлено по бюллетеням RustSec: `bytes` 1.12.1 (RUSTSEC-2026-0007,
переполнение в `BytesMut::reserve`), `crossbeam-epoch` 0.9.21
(RUSTSEC-2026-0204), `tracing-subscriber` 0.3.20 (RUSTSEC-2025-0055,
ANSI-последовательности из пришедших данных попадали в журнал),
`anyhow` 1.0.104 (RUSTSEC-2026-0190), `rand` 0.8.8 (RUSTSEC-2026-0097),
`memmap2` 0.9.11 под `blake3` (RUSTSEC-2026-0186), `event-listener`
5.4.2 в GUI (RUSTSEC-2026-0221). Все обновления — в пределах Rust 1.82.

## Проверки

`scripts/supply-chain.sh` делает то же, что задача «Supply chain» в CI
(`.github/workflows/supply-chain.yml`). Задача идёт при каждом изменении и
каждый день: бюллетени выходят и без изменений в коде. Любая ошибка
останавливает CI.

**cargo-deny** (`deny.toml`) проверяет:

* бюллетени RustSec: уязвимость, небезопасный (unsound) код, брошенный
  крейт, отозванная версия — во всём графе. По умолчанию небезопасный код
  ищется только в крейтах, названных в `Cargo.toml`, так пропускался
  `memmap2` под `blake3`;
* лицензии: только позволяющие выпускать MIT-бинарники как есть;
* дубли — две версии одного крейта. Отдельным прогоном проверяется сборка
  без GUI: пропуск дерева GUI снимает с проверки каждую версию, которую
  GUI где-либо использует;
* источники: только crates.io, без git и чужих реестров.

Исключения, каждое с причиной:

| Что | Почему |
|---|---|
| RUSTSEC-2026-0194, RUSTSEC-2026-0195, `quick-xml` 0.36 (`zbus_xml` под `zbus-lockstep`, под `atspi-common`): разбор недоверенного XML за квадратичное время и без предела памяти | `atspi-common` разбирает XML только в своих тестах (макрос `validate` порождает код под `#[cfg(test)]`): своих описаний интерфейсов AT-SPI, при работе программы — ничего. `zbus_xml` без него требует Rust 1.87 |
| `ttf-parser` — брошен | Шрифты epaint (через `ab_glyph`); читает только шрифты, встроенные в GUI |
| дубли в дереве `eframe` (около двадцати: два поколения `rand`, `syn`, `thiserror`, `bitflags`, `objc2`) | egui 0.32 |
| дубли в дереве `rfd` (`rand` 0.9 рядом с 0.8 этого крейта) | Диалоги выбора файла через портал (`ashpd`) |
| дубли `windows-sys` | Сгенерированные привязки к Windows API без своего кода |
| MPL-2.0 у `option-ext` (из `dirs`) | Слабый копилефт по файлам; файлы не изменены, исходник на crates.io |
| OFL-1.1, Ubuntu-font-1.0 у `epaint_default_fonts` | Шрифты, встроенные в GUI |

Все исключения, кроме `windows-sys` и `option-ext`, приходят из GUI
(egui 0.32, rfd 0.15). Проверено, что каждое нужно: без любого из них
проверка падает. До egui 0.32 GUI был на 0.24: уязвимый `webbrowser` 0.8
(RUSTSEC-2026-0257; `clippy.toml` запрещал всё, что выводит ссылку),
брошенные `derivative` и `instant`, `memmap2` 0.5 и около тридцати
дублей. Исправленный `webbrowser` 1.2.2 требует Rust 1.85; поэтому GUI
требует 1.85, остальное — по-прежнему 1.82.

**cargo-audit** — уязвимости ещё раз, другой реализацией, по той же базе
RustSec. Проверяет и `fuzz/Cargo.lock`. Небезопасный код в транзитивных
зависимостях нашёл именно он: cargo-deny с настройками по умолчанию его
пропустил. Исключения — те же, что для `quick-xml` в `deny.toml`
(`.cargo/audit.toml`).

**Лок фаззинга.** У фаззеров своё рабочее пространство и свой
`fuzz/Cargo.lock`. Он разошёлся с `Cargo.lock` на 72 крейта, и фаззеры
проверяли не те версии, что идут в выпуск. Теперь `scripts/supply-chain.sh`
падает, если в `fuzz/Cargo.lock` есть версия, которой нет в `Cargo.lock`
(кроме самого libFuzzer).

**cargo-vet** (`supply-chain/`) требует, чтобы каждый крейт был проверен
кем-то, кому доверяют, или назван исключением. Импортированы аудиты
Mozilla, Google, Bytecode Alliance, ISRG, Zcash и Embark. Ими покрыто 150
крейтов целиком и 7 частично; 372 крейта — исключения (с GUI на egui 0.32
их стало больше: его дерево шире). В сборке без GUI покрыто 56 из 161. Шесть крейтов TLS тоже исключения: импортированные
аудиты есть только на старые версии (`rustls` 0.21, `rustls-webpki`
0.101, `tokio-rustls` 0.24, `untrusted` 0.7), а разница до нынешних — десятки
тысяч строк. Среди непокрытых почти вся криптография (`aes-gcm`,
`chacha20poly1305`, `x25519-dalek`, `curve25519-dalek`, `blake3`, `argon2`,
`ml-kem`), а также `tokio`, `socket2`, `quinn-udp`. Отсюда два следствия:

* новый крейт или новая версия не пройдут CI, пока их не проверят
  (`cargo vet certify`) или не внесут в исключения явно;
* список исключений — это долг аудита. `cargo vet suggest` показывает, что
  проверить дешевле всего (часто это разница двух версий в несколько
  строк).

Доверенные издатели (`cargo vet trust`) не заданы. Это решение о доверии
людям, например авторам RustCrypto или dtolnay, и принимает его владелец
проекта.

**Действия GitHub** во всех workflow закреплены по коммиту, инструменты
(`cargo-deny`, `cargo-audit`, `cargo-vet`, `cargo-fuzz`, `cargo-mutants`,
`cargo-cyclonedx`)
— по версии. Образ, в котором ClusterFuzzLite собирает цели, закреплён по
хешу (`.clusterfuzzlite/Dockerfile`). Образы самого ClusterFuzzLite
названы внутри его действия меткой `v1`, и снаружи их не закрепить.

## Воспроизводимая сборка

`scripts/repro.sh` собирает выпускные бинарники для Linux из коммита
(`git archive`, не из рабочего дерева) в контейнере
`rust:1.95.0-slim-bookworm`, закреплённом по дайджесту: компилятор,
компоновщик и C-библиотека одни и те же. Пути к исходнику и реестру
приводятся к одному виду (`--remap-path-prefix`); больше для совпадения
ничего не понадобилось. GUI-варианту системные библиотеки, кроме
C-библиотеки образа, не нужны: оконные и графические загружаются при
запуске, а диалоги выбора файла идут через портал рабочего стола
(rfd 0.15; до перехода на egui 0.32 он компоновался с GTK 3 из снимка
архива Debian).

`scripts/repro.sh check` собирает дважды. Вторая сборка отличается всем,
кроме исходника и образа: каталог, пользователь, umask, часовой пояс,
локаль, имя хоста, число параллельных задач и реестр, скачанный заново.
Проверка проходит, только если все бинарники совпали побайтно. Так
проверены сборка без GUI и с GUI (`docs/evidence/supply-chain/`). Контроль:
та же пара сборок без приведения путей даёт разные бинарники, значит
проверка различает.

Чего это не даёт:

* сборка воспроизводима в этом образе. На другом дистрибутиве или с
  другим компоновщиком байты будут другие — образ входит в определение
  сборки;
* бинарники для Windows и macOS собираются на машинах GitHub и не
  воспроизводимы.

## Выпуски

`.github/workflows/release.yml` запускается на тег `v*` и делает:

* бинарники для Linux: так же, как `scripts/repro.sh build`, без GUI (все
  четыре) и с GUI (отправитель и получатель); архивы тоже одинаковы при
  каждой сборке. Для Windows и macOS — на машинах GitHub;
* SBOM CycloneDX 1.5 для каждого архива (`cargo-cyclonedx`): все крейты
  той сборки с версиями, лицензиями, purl и SHA-256 из `Cargo.lock`;
* `SHA256SUMS` по всем файлам;
* аттестацию происхождения (SLSA provenance), подписанную через Sigstore
  удостоверением самого workflow. Ключа, который надо хранить, нет;
  подпись записывается в открытый журнал Sigstore;
* черновик выпуска. Публикует его человек.

Проверка скачанного:

```
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify sharp256-v0.6.0-x86_64-linux.tar.gz --repo Echo-Eins/SHARP256
scripts/repro.sh build v0.6.0     # SHA256SUMS, как внутри архива для Linux
REPRO_VARIANT=gui scripts/repro.sh build v0.6.0     # для архива -gui
```

Аттестация доказывает, что файл собран этим workflow из этого коммита
этого репозитория. Она не защищает от того, кто может менять сам
репозиторий или workflow. От этого защищает воспроизводимость: сборку
можно повторить у себя и сравнить.

Сам workflow ещё ни разу не запускался: тег не отправлялся. Он проверен
`actionlint`, а его сборка для Linux — это `scripts/repro.sh`, проверенный
здесь.

## Что осталось

* 372 исключения cargo-vet, в сборке без GUI — 105, среди них
  криптография и весь TLS (`ring`, `rustls`).
* Воспроизводимость сборки без GUI с `ring` не перепроверена:
  `scripts/repro.sh check` занимает машину надолго и запускается в CI или
  по просьбе.
* GUI на egui 0.32: три бюллетеня в исключениях (`quick-xml` — только в
  тестах `atspi-common`; брошенный `ttf-parser`) и около двадцати дублей.
  Без `ttf-parser` шрифты рисует egui 0.34, но он требует Rust 1.92.
* `ml-kem` 0.2 тянет предварительную версию `kem` 0.3.0-pre.0 (Р25).
  cargo-deny предварительные версии не отмечает.
* Выпуски для Windows и macOS не воспроизводимы.
