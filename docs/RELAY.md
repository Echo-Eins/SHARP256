# Свой ретранслятор

Ретранслятор (`sharp-relay`) — место встречи и, когда прямой путь не
открывается, перевозчик: через него идут уже зашифрованные датаграммы, и
прочесть или подменить их он не может (THREAT_MODEL.md, Н4б). Он нужен,
когда обе стороны за NAT, раздающим порт на каждое назначение, когда у
одной стороны закрыт UDP, и как запасной путь вообще. Хватает самой
маленькой виртуальной машины с публичным адресом: память — десятки
мегабайт, процессор почти не нужен, нужна полоса.

## Что открыть

| Порт | Протокол | Зачем |
|---|---|---|
| 5560 | UDP | регистрации получателей, знакомства, служебный обмен |
| 5560 | TCP | то же для клиентов без UDP (`--no-tcp` выключает) |
| 443 | TCP | то же по TLS, для сетей, выпускающих только HTTPS (`--tls`) |
| 3478, 3479 | UDP | STUN: как клиентов видно снаружи (`--stun`) |
| 32768–60999 | UDP | порты пар: на каждую перевозимую передачу ретранслятор открывает свой порт (диапазон — `net.ipv4.ip_local_port_range` системы) |

Пример для nftables (в цепочке `input`, где по умолчанию всё запрещено):

```
udp dport { 5560, 3478, 3479, 32768-60999 } accept
tcp dport { 5560, 443 } accept
```

Для ufw: `ufw allow 5560`, `ufw allow 443/tcp`, `ufw allow 3478:3479/udp`,
`ufw allow 32768:60999/udp`. У облачного провайдера те же порты открываются
ещё и в его «группе безопасности».

Порт 443 должен быть свободен: веб-сервер на той же машине его займёт. Тогда
либо другой порт (`--tls [::]:8443`, а клиентам — `--relay-tls-port 8443`),
либо отдельный адрес.

## Установка как службы

Бинарник — из выпуска или собранный (`cargo build --release
--no-default-features --features nat-traversal,tls --bins`). Затем, от root:

```
install -m 0755 sharp-relay /usr/local/bin/
install -m 0644 contrib/systemd/sharp-relay.service /etc/systemd/system/
install -d -m 0755 /etc/sharp-relay
printf 'RELAY_ARGS=--stun 203.0.113.7\n' > /etc/sharp-relay/relay.env   # адрес этой машины
systemctl daemon-reload
systemctl enable --now sharp-relay
journalctl -u sharp-relay -n 20
```

В журнале при запуске — строка `Receivers: --relay sh-…@<this host>:5560`:
это ID ретранслятора. Получатели пишут `--relay <ID>@<адрес>:5560`;
отправители — `--relay <адрес>:5560` или с ID, если нужен TLS (клиент
проверяет, что сессия TLS принадлежит ретранслятору с этим ID, и без ID
TLS к нему не идёт).

Служба (`contrib/systemd/sharp-relay.service`) работает от пользователя,
которого systemd создаёт на время работы, без привилегий, кроме права
занять порт 443; ключ ретранслятора лежит в `/var/lib/sharp-relay/` и
создаётся при первом запуске. **Сохраните его копию**: получатели знают
ретранслятор по ID, а новый ключ — новый ID. Проверено: `systemd-analyze
verify` и `systemd-analyze security` (уровень открытости 1.5, «OK»), а
ретранслятор запускался под теми же фильтрами системных вызовов и памяти.

Без systemd — то же одной строкой (порт 443 тогда нужно разрешить:
`setcap cap_net_bind_service=+ep /usr/local/bin/sharp-relay`):

```
sharp-relay --bind [::]:5560 --tls [::]:443 --stun 203.0.113.7 --identity /var/lib/sharp-relay/relay.key
```

## Кого пускать

Без списков ретранслятор открыт: любой получатель, доказавший свою
личность, может сделать его местом встречи и возить через него передачи
за ваш счёт. При запуске он говорит об этом прямо. Для полевых испытаний
и своего круга — списки и квоты (в `RELAY_ARGS`):

```
RELAY_ARGS=--stun 203.0.113.7 --allowed-receivers /etc/sharp-relay/receivers.txt --client-rate 50M --client-quota 20G --total-rate 200M
```

* `--allowed-receivers FILE` (или `--allow-receiver ID`, сколько угодно
  раз) — какие получатели могут регистрироваться: по ID на строку, `#` —
  комментарий. ID получателя печатает `sharp-receiver --id`.
* `--allowed-senders FILE` — каких отправителей проводить; им тогда нужен
  ID ретранслятора (`--relay <ID>@<адрес>:5560`), чтобы доказать, кто они.
* `--client-rate` — скорость на клиента (адрес IPv4 или сеть IPv6 /64),
  `--client-quota` — объём на клиента в час, `--total-rate` — на всех
  вместе, `--pair-bytes` — на одну передачу.

## STUN

`--stun <адрес>` — STUN-сервер на этой машине, порты 3478 и 3479: клиенты
узнают у него, как их видно снаружи. С одним адресом он измеряет, меняется
ли внешний порт с назначением; чтобы измерить ещё и фильтрацию NAT
(RFC 5780), нужен второй адрес той же машины: `--stun <первый> --stun
<второй>`. Адреса — свои, этой машины: сервер отвечает только с них.

## Что видит ретранслятор

Содержимое передач — нет: оно зашифровано сквозным образом, и ретранслятор
не участвует в рукопожатии. Видит: ID получателей, которые регистрируются;
адреса обеих сторон; когда и сколько байтов прошло через каждую пару.
Служебный обмен с ним открыт и виден наблюдателю на пути к нему (Р11).
Журнал службы содержит ID и адреса; храните его соответственно.

## Обновление

Новый бинарник на место старого, затем `systemctl restart sharp-relay`.
Регистрации ретранслятор держит в памяти, и перезапуск их теряет:
получатели регистрируются заново сами — при следующем обновлении, самое
позднее через срок аренды (`--lease`, 120 с). Передачи, которые в этот
момент шли через ретранслятор, теряют его порт пары: сессия ищет другой
путь, как после любого обрыва, а если не найдёт — отправитель выходит,
сохранив состояние, и повторный запуск продолжит с места остановки.
Перезапускайте, когда через него ничего не идёт (`journalctl -u
sharp-relay` покажет, какие пары открыты).
