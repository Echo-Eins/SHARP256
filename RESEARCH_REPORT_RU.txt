РЕЗЮМЕ ПРОЕКТА:
─────────────────
SHARP-256 (Swift Hash Assurance Rust Protocol) - это высокопроизводительный
протокол передачи файлов с интеграцией WebRTC ICE, поддержкой обхода NAT и
верификацией целостности через BLAKE3. Проект достигает 80-90% пропускной
способности сети и поддерживает сложные сценарии NAT (включая symmetric NAT).

ОСНОВНАЯ ЦЕЛЬ:
Создать высокопроизводительный, надежный протокол передачи файлов, который:
1. Достигает 80-90% пропускной способности сети
2. Поддерживает все типы NAT (включая symmetric)
3. Работает как в локальных сетях, так и в интернете
4. Устойчив к разрывам соединения с возможностью возобновления

ПОТОК ПЕРЕДАЧИ ДАННЫХ:
─────────────────────
Sender:
1. Открыть файл (mmap)
2. Инициализировать NAT/Connectivity
3. Читать блоки (256 KB)
4. Упаковать в пакеты с BLAKE3 хешем
5. Отправить партии (5-50 пакетов)
6. Получить ACK с feedback
7. Обновить SAO параметры
8. Повторять для каждого блока

Receiver:
1. Создать сокет
2. Инициализировать NAT/Connectivity
3. Получить пакеты
4. Буферизировать партию
5. Верифицировать BLAKE3 хеши
6. Отправить ACK
7. Записать на диск
8. Сохранить состояние для возобновления

4. ОСНОВНЫЕ АЛГОРИТМЫ И КРИПТОГРАФИЯ

ВЕРИФИКАЦИЯ ЦЕЛОСТНОСТИ:
───────────────────────
• BLAKE3 - современный криптографический хеш
  ├── 32-байт выход (256 бит)
  ├── Параллелизм на всех уровнях
  ├── Инкрементальное хеширование
  └── Более быстро, чем SHA-3 на практике

Per-packet verification:
├── Каждый пакет содержит свой BLAKE3 хеш
├── Позволяет обнаружить повреждение на сетевом уровне
└── Быстрое исправление (пересылка одного пакета)

Per-batch verification:
├── Хеш всей партии (5-50 пакетов)
├── Более эффективно чем перепроверка всех пакетов
└── Быстрый ACK цикл

Full file verification:
├── Финальный хеш всего файла
├── Гарантия конца-в-конец целостности
└── Совпадение с исходным хешем перед отправкой

АДАПТИВНАЯ ОПТИМИЗАЦИЯ (SAO):
─────────────────────────────
Метрики отслеживаются:
1. RTT (Round Trip Time)
   ├── Из ACK сообщений (ping_ms поле)
   ├── Влияет на выбор таймаутов
   └── Используется в score = ... * (1 / (1 + rtt/100))

2. Потери пакетов (loss_rate)
   ├── Рассчитывается из ACK feedback
   ├── Рекомендуемые переотправленные пакеты
   └── Влияет на score как (1 - loss_rate)

3. Пропускная способность (bandwidth_utilization)
   ├── Bytes sent / elapsed_time
   ├── Нормализуется к 1 Gbps
   └── Множитель в score

Score формула:
  score = (1 - loss_rate) * bandwidth_utilization * (1 / (1 + rtt/100))

Пороги адаптации:
  • score > 0.8 → увеличить batch_size (до MAX 50)
  • score < 0.4 → уменьшить batch_size (до MIN 5)
  • иначе → сохранить или менять на ±5 пакетов

ШИФРОВАНИЕ:
───────────
Optional TLS 1.3:
├── rustls (чистый Rust)
├── Сертификаты/ключи
├── Полная forward secrecy
└── 10-15% overhead

Relay header encryption (для SHARP relay):
├── AES-GCM-256 или ChaCha20Poly1305
├── HKDF-SHA256 для вывода ключей
├── Шифруется только заголовок (не данные)
├── Снижает overhead, защищает privacy
└── x25519-dalek для ECDH

6. КЛЮЧЕВЫЕ RFC СТАНДАРТЫ
═══════════════════════════════════════════════════════════════════════════════

RFC 8489 (STUN) - ✓ Реализовано
├─ MESSAGE-INTEGRITY-SHA256 (новое в RFC 8489, vs старый MD5)
├─ Binding Requests/Responses
├─ NAT behavior detection
└─ Статус: действующий (Feb 2020), заменил RFC 5389

RFC 8445 (ICE) - ✓ Реализовано
├─ Candidate gathering
├─ Connectivity checks
├─ Nomination
├─ Controlling agent role
└─ Статус: действующий (Feb 2020)

RFC 8838 (Trickle ICE) - ✓ Реализовано
├─ Инкрементальная отправка кандидатов
├─ Параллельные проверки connectivity
└─ Ускорение установления соединения

RFC 5768 (mDNS in ICE) - ✓ Поддержано
├─ Защита приватности имен хостов
├─ Для браузеров и WebRTC
└─ Обфускация локальных IP

RFC 8656 (TURN) - ✓ Реализовано
├─ Relay allocation
├─ Permissions
├─ Channels
├─ DTLS-SRTP support

RFC 6887 (PCP) - ✓ Реализовано
├─ Явное управление NAT
├─ IPv4 и IPv6 поддержка
├─ Nonce-based authentication
└─ Совместимость с NAT-PMP

RFC 6886 (NAT-PMP) - ✓ Реализовано (legacy)
├─ Apple NetBIOS port mapping
├─ Без аутентификации
└─ IPv4 only

UPnP IGD v2.0 - ✓ Реализовано
├─ DeviceProtection DCP
├─ IPv6 поддержка
├─ Обратная совместимость с v1.0
└─ Проброс портов (AddPortMapping)

RFC 5780 (NAT Behavior Discovery) - ✓ Реализовано (частично)
├─ Полная 75% точность требует специальной инфраструктуры
├─ Многосерверное обнаружение (эмуляция)
├─ Вероятностная классификация
└─ Используется как fallback
